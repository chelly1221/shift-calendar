# Android 음성 캘린더 연동

2026-09-10, Android 0.2.12(versionCode 14)과 PC Supertonic 3 음성 전환 구현 기준. 음성 교체와 슬래시 읽기 수정에는 PC 갱신만 필요하며 기존 Android 0.2.11 APK도 호환된다. 휴대폰 음악 재생 보호에는 Android 0.2.12가 필요하다. Android 앱과 PC Electron 앱이 같은 공유기의 사설 IPv4 네트워크에서 직접 연결된다. 앱을 열면 PC를 자동으로 찾으며 비밀키·계정·IP 입력이 없다. PC가 여러 대면 목록에서 선택한다. PC가 유선 LAN, 휴대폰이 같은 공유기의 Wi-Fi인 구성도 가능하다.

## 사용 순서

1. 이 변경이 포함된 PC 캘린더를 실행한다. 휴대폰 연결은 PC 시작 시 자동으로 켜진다.
2. [근무물어봐-0.2.11.apk](../app/release/0.0.0/win-unpacked/근무물어봐-0.2.11.apk)를 설치하고 같은 Wi-Fi에서 앱을 연다.
3. 마이크·알림 권한을 허용하고 ‘까치야, 내일 야간 누구야?’처럼 한 문장으로 말한다. 안내를 기다리는 단계 없이 질문을 처리한다. 직접 입력도 가능하다. 홈 화면·화면 꺼짐 상태의 음성 대기 지원은 기기의 기본 음성 서비스에 따라 달라진다.
4. 답변은 Android 화면에 표시하고 PC의 Windows 기본 스피커로 읽으며 긴 목록도 끝까지 읽는다. 다시 읽기·읽기 중지는 PC 재생을 제어한다. 날짜나 일정 선택을 되물으면 상시 대기 모드에서 호출어 없이 ‘내일’, ‘오후’, ‘두 번째’처럼 답할 수 있다. 이름 후보를 되물으면 ‘김수헌’처럼 이름만 답할 수 있다.
5. 일정 등록·변경·삭제·완료 처리는 내용을 먼저 보여주고 읽어준다. 상시 대기 모드는 읽기가 끝나면 자동으로 “확인” 또는 “취소”를 듣는다. 수동 모드는 음성 버튼이나 해당 버튼을 누른다. PC 확인 대기는 2분이며 상시 대기 클라이언트는 110초 후 확인을 만료시킨다.

PC 설정의 **안드로이드 음성 도우미**에서 상태를 확인하거나 끌 수 있다. 같은 네트워크 기기는 인증 없이 조회·조작할 수 있다. 다음 PC 앱 시작 시 연결은 다시 켜진다. PC 앱 종료·절전 중에는 조회와 조작을 할 수 없다.

## 처리 구조

`Android 음성인식 → 질문 문자열 → LAN HTTP → 키워드·날짜 규칙 → PC 로컬 일정/공유 근무 계산 → 정해진 답변 문장 → PC 로컬 AI 합성 → Windows 기본 스피커 + Android 화면`

PC는 Supertonic 3의 한국어 F1 AI 합성 음성을 사용한다. `onnxruntime-node` CPU 추론을 별도 worker thread에서 5단계로 수행하며 세션을 재사용한다. 모델 준비와 추론이 Electron 메인 이벤트 루프를 점유하지 않도록 분리한다. Windows SAPI·Microsoft Heami와 Android 로컬 TTS는 사용하지 않는다. Windows 기본 출력 장치로 재생하며 장치 선택·시스템 음소거는 사용자의 설정을 따른다. 고정 PowerShell 재생 명령을 숨김 프로세스로 실행하고, 메모리에서 만든 44.1 kHz 모노 PCM16 WAV를 base64 JSON stdin으로 전달해 `System.Media.SoundPlayer`로 읽는다. 사용자 텍스트를 명령문에 삽입하지 않는다.

답변은 FIFO로 재생하며 줄과 최대 120자 길이에 따라 나눈다. 현재 구간을 읽는 동안 다음 한 구간만 미리 합성하여 긴 목록 전체가 만들어질 때까지 기다리지 않는다. 중지하면 재생을 종료하고 남은 합성을 취소한다. 공유 모델의 합성 요청은 직렬 처리하며 초기화 실패나 요청 취소 이후 다시 요청할 수 있다. 재생 준비는 45초, 개별 구간은 최소 30초 또는 글자 수에 비례한 한도로 정지를 감지하고 전체 목록의 총 재생 시간은 제한하지 않는다. 마지막 구간의 재생 완료와 프로세스 종료를 확인해야 완료로 처리한다.

화면 답변에는 `/` 등 원래 문자를 유지한다. 음성용 문장에서는 목록 구분 기호를 쉼으로 바꿔 ‘슬래시’라고 읽지 않는다. 예를 들어 화면의 `일근 김민수 / 주간 A조 이영희`는 두 항목 사이에 짧게 쉬어 읽는다. 음성 정규화는 PC 재생 경로에 적용되므로 다시 읽기에도 동일하게 반영된다.

약 398 MB의 공개 모델은 `npm run voice:prepare`에서 [manifest](../app/voice-model-manifest.json)에 고정한 Hugging Face revision과 파일별 SHA-256으로 검증한다. 다운로드한 임시 파일은 검증 후에만 정식 경로로 교체하며, 이미 유효한 파일은 재사용한다. PC 빌드는 모델을 `resources/voice-model/`에 포함한다. 질문·이름·답변을 외부 TTS 서버에 보내지 않으며 설치된 PC의 추론에는 인터넷 연결이 필요하지 않다. 코드의 MIT 고지와 모델의 OpenRAIL-M 원문·사용 제한은 [음성 구성요소 이용 조건](../app/THIRD_PARTY_VOICE.md)과 함께 배포한다.

해당 PC에서 공개 안내 문장 두 개를 한국어 F1·5단계로 합성한 결과, 모델 초기화 약 1.05초와 약 4~5초 음성 생성 약 0.69~0.72초, 프로세스 메모리 약 516 MB를 측정했다. 이는 해당 PC의 짧은 샘플 결과이며 다른 PC·긴 목록의 지연이나 Android 실기기 인식 정확도를 나타내지 않는다.

질문 판정과 답변 문장 생성에는 LLM API를 사용하지 않고 기존 키워드 규칙을 유지한다. 완성된 문장을 소리로 바꾸는 단계에만 로컬 AI 모델을 사용한다. 0.2.6부터 마이크 포그라운드 서비스는 호출어와 질문을 같은 `LiveQuestionRecognizer`의 Android 기본 인식기로 함께 듣는다. 호출어만으로 인식을 끊거나 안내를 읽지 않는다. 최종 결과의 호출어 뒤 질문만 PC에 보내며 부분 결과는 명령으로 제출하지 않는다. 질문 버튼·확인 응답도 같은 인식기를 사용한다. Vosk 엔진·모델·버퍼 입력·기기 내 전용 옵션은 제거했다. 대기 음성도 기본 서비스에 따라 서버에서 처리될 수 있으며 앱은 음성을 파일로 저장하지 않는다. 0.2.10부터 TTS 중에도 호출어가 있는 질문을 인식하고 응답 텍스트를 제외한 최종 질문을 대기열에 넣는다. 전체 재생이 끝나면 순서대로 처리한다.

0.2.7은 정상 결과·무음 종료에서 인식기 연결을 유지하고 다음 세션을 시작한다. 정상 대기마다 `cancel/destroy/create`를 반복하던 연결 재생성을 제거했다. 진행 중 캡처 취소·실제 오류·응답 정지는 연결을 폐기해 늦은 확인 콜백이 다음 질문에 섞이지 않게 한다. 준비가 1.5초 이상 늦을 때만 지연 상태를 표시하고, 10초 동안 준비 응답이 없으면 재연결한다. 동일한 대기 상태로 UI와 알림을 반복 갱신하지 않는다. 기본 서비스 자체의 연속 인식 제약은 남아 있다.

서비스는 앱을 화면에 연 상태에서 시작하고 화면 꺼짐 이후에도 유지한다. 대기 알림에 종료 버튼을 제공하며 앱에서 배터리 설정을 열 수 있다. 재부팅·강제 종료·제조사 절전 정책으로 서비스가 종료되면 앱을 다시 열어야 한다. 기본 인식기는 세션을 반복 시작하므로 서비스에 따른 재연결 공백·요청 제한·전력 및 네트워크 사용량이 생길 수 있다. 화면 꺼짐 중 실제 마이크 사용과 인식 정확도는 실기기 확인이 필요하다. [Android 마이크 포그라운드 서비스](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone), [Android SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer).

응답 데이터는 PC 로컬 캐시 기준이다. Google 동기화가 늦으면 원격 최신 상태와 다를 수 있다. 쓰기는 기존 PC 등록·삭제 로직과 Outbox를 통과한다. Prisma 스키마 변경은 없다. 참석자 이메일 초대는 음성 명령에 포함하지 않는다.

### 0.2.11 화면과 빠른 설정

가로 방향을 강제하지 않는다. 기기의 `smallestScreenWidthDp`가 600 이상이고 현재 창 너비도 600dp 이상일 때만 태블릿용 두 영역을 표시한다. 스마트폰은 가로로 돌려도 휴대폰용 세로 배치를 유지하며, 태블릿도 좁은 분할 창에서는 휴대폰 배치를 사용한다. 회전·창 크기 변경 시 다시 배치하고 큰 글자 설정에서는 버튼을 세로로 쌓는다.

새 아이콘의 ‘까치야 상시 듣기’ 빠른 설정 타일로 대기를 제어한다. Android 13(API 33) 이상은 앱 설정의 ‘빠른설정에 상시듣기 추가’로 추가를 요청하고 이전 버전은 시스템 빠른 설정 편집에서 추가한다. OFF는 실행 중인 서비스를 즉시 종료한다. ON은 마이크 포그라운드 서비스의 시작 제약에 따라 Activity를 열고 권한을 확인한 후 시작한다. 타일 상태는 실제 서비스 시작·종료·오류와 동기화한다.

연결된 Android 실기기가 없어 실제 PC 스피커 응답 중 음성인식, 타일 추가·ON/OFF, 휴대폰·태블릿 회전 및 분할 화면은 실기기 검증이 남아 있다. 아래 버전별 검사 수치는 각 과거 구현의 기록이다.

### 0.2.4 질문 인식 회귀 수정

초기 0.1.0 APK의 DEX에는 Android 기본 `SpeechRecognizer` 호출이 있으며 Vosk 인식기는 없다. 0.2.1~0.2.3의 상시 대기는 Vosk로 질문을 먼저 받아쓴 후 Android 13의 버퍼·분할 인식을 시도했다. 버퍼 방식 미지원, 일반 `onResults` 수신, 오류 또는 8초 제한에서 내장 전사를 사용자에게 알리지 않고 제출했다. 기존 합성음성 검사에도 질문 전사가 `야단 누구 야`처럼 변한 기록이 있어 호출어 감지 성공만으로 문장 인식 정확도를 검증할 수 없었다. 실제 사용자 기기의 Android 버전·선택한 엔진·콜백 로그는 확보하지 못했으므로 어느 분기가 실행됐는지는 확정하지 않았다.

수정본은 질문 버튼·변경 확인을 기본 인식기로 직접 처리한다. 버퍼 인식에 실패하면 내장 전사를 제출하지 않고 기본 마이크로 다시 듣는다. 이후 같은 서비스 세션에서는 호출어 안내 후 기본 인식기를 사용한다. 대기 마이크의 해제가 끝난 뒤 새 마이크를 열고, 취소된 세션의 늦은 결과·부분 결과를 명령으로 보내지 않는다. 기본 모드의 화면에도 Vosk의 임시 전사를 표시하지 않으며, Vosk가 빈 문장을 반환해도 캡처한 음성은 기본 엔진에서 인식할 수 있다. 기기 내 인식만 쓰겠다는 사용자 설정은 유지한다.

### 0.2.5 기본 질문 인식 통일

사용자 요청에 따라 기본 음성인식으로 모든 질문 경로를 통일했다. 호출어용 인식기는 질문을 받아쓰는 API나 전사 콜백을 갖지 않는다. 질문 버튼과 음성 서비스가 같은 기본 인식기 구현과 취소·오류 처리를 사용한다. 이전 `localOnly` 설정은 제거하며 결과를 다른 엔진으로 대체하지 않는다. 기본 인식기는 상시 연속 인식을 위한 API가 아니므로 기존 화면 꺼짐 상태의 호출 대기를 유지하기 위해 호출어 감지만 별도로 둔다. [Android SpeechRecognizer 문서](https://developer.android.com/reference/android/speech/SpeechRecognizer).

## 지원 질문

0.2.6 상시 대기에서는 아래 질문 앞에 ‘까치야’를 붙여 한 번에 말한다. 예: ‘까치야 내일 근무자 누구야?’. 호출어만 말하면 안내 없이 다음 질문을 기다린다. 질문 버튼이나 직접 입력은 호출어가 필요 없다. 무음은 조용히 다시 듣고, 일시 오류는 1~30초 간격으로 재연결하며 서비스 요청 제한은 30초 대기한다. PC 자동 검색 중 들어온 질문도 처리한다.

이름과 제목은 PC에 등록된 값으로 바꾼다. 날짜·대상·종류·인원/건수 조건을 조합하며 복잡한 부정문이나 여러 종류의 질문은 다시 묻는다.

조회 날짜: 오늘·내일·모레·글피·어제·그제, 이번/다음/지난 주, 다음 주 금요일, 이번/다음 주말, 이번/다음/지난 달, 9월 15일, 2027년 1월 3일, 2026-12-31, 9월 10일부터 9월 15일까지. 명시한 날짜 범위는 한 번에 93일 이내, 현재 기준 5년 전~2년 후다. 날짜를 생략한 일반 조회는 오늘 기준이다. 다음 일정은 향후 90일을 검색한다. 단, ‘휴가 언제야’, ‘다음 휴가 언제야’, ‘앞으로 예정된 휴가 알려줘’는 오늘부터 저장된 예정 휴가를 전부 날짜순으로 반환한다. 첫 항목·90일 제한과 일정 하나 선택 안내를 적용하지 않는다. 유한 반복은 COUNT·UNTIL의 마지막 회차와 취소·변경 예외를 포함한다. 끝없는 반복은 최소 1년 및 함께 저장된 휴가의 마지막 날짜까지 조회하고 실제 조회 마지막 날짜를 안내한다. 기존 반복 확장의 시리즈별 10,000 후보 상한은 유지한다. 요청 범위의 긴 목록도 전부 반환하고 끝까지 읽는다.

연도를 생략한 월·날짜는 PC의 오늘에서 가장 가까운 연도로 해석한다. 월만 있으면 월 간격, 월·일이 있으면 날짜 간격으로 비교하며 동률이면 미래를 선택한다. ‘1월 일정 알려줘’, ‘9월 달력 알려줘’와 일정 초안에 같은 규칙을 사용한다. 명시한 숫자 연도·올해·내년·작년은 우선한다. 날짜 범위는 가능한 93일 이내의 구간 중 오늘과 가장 가까운 구간으로 함께 해석해 연말·연초와 윤년을 처리한다.

근무 응답은 주간/야간 조, 일근자, 대체근무자, 휴가와 교육을 반영한다. 근무에서 제외되는 휴가·교육자는 이름과 부재 설명을 모두 생략한다. 부분 휴가는 이름과 인원에 포함하되 뱃지와 사유를 말하지 않는다. 알려진 명단이 전원 부재면 ‘없음’ 또는 ‘0명’, 배정·구성원이 등록되지 않았으면 ‘미등록’으로 구분한다. PC 오늘의 근무 카드도 전원 부재는 `A조 근무자 없음`, 구성원 미등록은 `A조 미지정`으로 표시한다. 다음 근무 조회는 부재인 배정을 건너뛴다. 휴가·교육 자체를 묻는 질문은 대상자를 표시한다. 과거 조원 구성 이력이 없으므로 과거 날짜의 실제 근무자 이름은 확정하지 않는다.

`A조 근무자 누구야?`처럼 날짜·주간·야간 없이 조만 지정하는 질문은 근무 설정의 해당 조 명단을 그대로 반환한다. 이 경우 휴가·교육이나 오늘 배정 여부로 구성원을 제외하지 않는다. 날짜나 주간·야간을 명시하면 위의 실제 근무 규칙을 적용한다.

답변은 공통 서두와 반복되는 출처 설명을 생략한다. 하루 전체 근무는 일근·주간·야간 세 줄, 인원 조회는 숫자, 이름이 지정된 일정의 시각·장소는 해당 값만 답한다. 일반 일정 목록에서는 여러 날을 조회해도 날짜를 생략하고, ‘언제’ 등 날짜를 직접 물으면 표시한다. 누락된 대상자·미등록과 변경 확인의 대상·시각·반복 범위는 유지한다. PC가 음성용 문자열을 여러 구간으로 나누어 전체 목록을 읽으며 Android 화면의 전체 답변도 유지한다. 출처는 별도 `source` 필드에 유지한다.

‘일정 알려줘’는 반복업무·중요·출장·교육·일반 다섯 타입을 이 순서로 묶어 `교육: 안전교육`처럼 타입과 제목만 제공한다. 날짜·시간·대상자를 덧붙이지 않는다. ‘일정 몇 건이야’, ‘다음 일정 언제야’도 이 다섯 타입을 대상으로 한다. 근무·휴가·공휴일·운용중지작업 등 특정 타입을 명시한 조회와 날짜·시각·장소를 직접 묻는 질문은 요청한 정보를 제공한다.

휴가자 조회는 날짜와 제목 없이 `김민수-연차` 형식으로 응답한다. 여러 일정·반복 회차·날짜 범위에서 같은 이름·뱃지를 합치며 한 사람의 여러 뱃지는 `김민수-연차·시간차(13:00~14:00)`처럼 묶는다. 특정 사람을 물으면 해당 이름만 표시하고, ‘언제’·시각·장소 질문에는 요청한 정보를 유지한다. 뱃지명은 PC에 저장된 `휴가종류` 값이다.

성 한 글자와 이름 두 글자로 등록된 사람은 고유한 이름만으로도 조회한다. `민수`, `민수씨`, `민수님`을 `김민수`로 연결하며 동명이면 성을 확인한다. 이름 뒤의 대리·과장·차장·부장·주임·계장·팀장·실장·국장·본부장·센터장·사원·소장과 `님` 존칭도 허용한다. 직함은 인식한 이름에 붙었을 때만 제거하며 다른 성을 붙인 미등록 이름이나 일정 제목의 일부를 사람으로 추정하지 않는다. 이름 없이 부르는 `소장`과 `소장님`은 PC 근무 설정의 첫 번째 일근자에 연결하며, 설정이 없으면 미등록을 알린다. 조회 맥락에는 실제 등록 이름을 보관한다. 시간차를 제외한 휴가의 날짜 질문에는 날짜·이름·뱃지만 표시하고 시각이나 종일 표시를 생략한다. 시간차는 `시각: ` 메모 → 휴가종류 괄호 → 제목의 시간차 괄호 → 실제 이벤트 시각 순서로 읽고 날짜·이름·시간차(시각)로 한 번만 표시한다. `~11:30`, `16:30~`, `9~11`, `3시부터`처럼 일부만 등록된 표기는 없는 값을 추정하지 않고 유지한다. 자정으로 저장된 날짜 범위를 종일 시간차로 해석하지 않으며, 실제 시각이 없으면 ‘언제’에는 시각 설명을 생략하고 ‘몇 시/시작/종료’에만 미등록을 알린다.

2026-09-09 답변·날짜 해석 수정: PC Vitest 473개, TypeScript·ESLint 통과. 근무자 부재 제외, 전원 부재와 미등록의 구분, 부분 휴가 유지, 활동 일정 필터, 휴가자 뱃지 중복 제거, 가장 가까운 연도·명시 연도·연말 범위·윤년을 검증했다. 응답 문장은 PC에서 생성하므로 PC Portable 갱신으로 적용한다. 음성 대기 안정화는 Android 0.2.7 업데이트가 필요하다. Android 단위 테스트 57개와 APK 빌드·서명·정렬 검사는 통과했으며 실제 태블릿의 장시간 대기 검증은 남아 있다.

### 0.2.11 조회 이름 인식 보정

`김수원 과장 휴가 언제야?`처럼 잘못 받아쓴 이름은 PC에 등록된 `김수헌`으로 연결할 수 있다. 먼저 등록 이름의 정확 일치를 우선하고, 유사 매칭은 같은 성의 한글 세 글자 실명에만 허용한다. 이름 두 음절 중 하나만 다르고 그 음절의 초성·중성·종성 차이가 두 자리 이하인 경우에만 후보로 삼는다. 짧은 이름·직함·별칭·다른 성을 유사 매칭하지 않는다. 입력과 등록명은 NFKC와 공백 제거로 비교한다.

후보가 여러 명이면 점수로 한 사람을 임의 선택하지 않고 이름을 되묻는다. 2분의 조회 선택 맥락에서 `김수헌`처럼 이름만 답해 원래 질문을 이어갈 수 있다. 보정은 조회 전용이며 일정 등록·변경·삭제 경로에는 적용하지 않는다.

### 0.2.8 전체 목록 읽기와 간결한 응답 (과거 기록)

0.2.8 응답 개선: 사람을 지정한 근무 질문은 `주간 A조입니다.`, `연차입니다.`처럼 상태만 제공한다. 일반 일정은 `오후 2시 안전교육`처럼 시간·제목 순서, 종일은 제목만 표시한다. 교육 대상을 직접 조회하면 대상자도 유지한다. 휴가자 화면 표기는 `김민수-연차`, 음성은 ‘김민수, 연차.’이며 숫자 시각은 오전·오후로 읽는다. 일정·휴가자 20개와 근무표 31일 출력 제한을 없애고 요청 범위의 전체 결과를 전달한다. Android는 전체 답변을 TTS 입력 길이 이내 구간으로 나누어 순서대로 읽으며 마지막 구간이 끝난 뒤 듣기로 돌아간다. 읽기 중지·새 질문은 남은 구간을 취소한다.

날짜·일정 조회가 모호하면 짧게 되묻고 2분간 조회 조건과 선택지를 유지한다. ‘오전’, ‘오후’, 시각, 순서, 제목으로 선택하며 삭제된 후보를 다른 일정으로 대체하지 않는다. 이 선택 맥락은 조회 전용이다. 일정 조작은 기존 확인·재검증 절차를 유지한다. PC Vitest 500개, Android 단위 테스트 66개, TypeScript·ESLint 통과. 실제 태블릿 TTS·마이크 검증은 남아 있다.

### 0.2.9 응답 및 실행 폴더 갱신

이름을 지정한 근무 질문도 휴가 사유 없이 `주간 A조입니다.` 또는 `근무 없음`으로 답한다. 휴가자 답변에서는 조회 기간 서두를 생략하고, 제목과 대상자에 같은 이름이 있어도 이름·뱃지를 한 번만 읽는다. 실제 실행 중이던 PC의 오래된 빌드에서 이전 휴가 문구가 반환되는 것을 확인했으므로, 이제 `app/release/0.0.0/win-unpacked`에 직접 갱신한다. `npm run build`는 실행 중인 프로그램을 종료한 뒤 이 폴더만 빌드하고 다른 배포본을 만들지 않는다.

Android 0.2.9는 음성 재생 완료 이후의 350ms 지연을 제거하고 읽는 동안 인식기 객체와 Android 13 이상의 지원 확인 요청을 준비한다. 마이크 캡처는 마지막 음성이 끝난 뒤 시작하며 인식기 연결을 재사용한다. 기본 서비스의 실제 준비 시간과 마이크 게인은 앱이 강제할 수 없다. 단위 테스트 70개로 즉시 전환·중복 완료 방지·사전 준비와 실패 복구를 검증했다. 실제 기기의 원거리 인식 검증은 남아 있다.

### 0.2.10 답변 중 다음 질문 저장

`SpokenQuestionQueue`는 재생 중의 호출어·최종 질문을 순서대로 보관하고 같은 질문의 중복 결과를 합친다. 일반 대화, 응답과 일치하는 전사, 현재·직전 재생 구간과 편집 거리가 작은 전사, 미래 작업으로 오해할 수 있는 확인·취소·다시 읽기는 제외한다. 질문 뒤에 붙은 동일 응답 문구도 제거한다. `SpeechPlayback`의 마지막 구간 완료 이후에만 질문을 꺼낸다. 마지막 부분 인식에 호출어가 있으면 10초 이내 최종 결과를 기다리고, 시간이 지나면 부분 문장을 실행하지 않는다. 실행 확인 대기 중에는 질문 처리를 보류하며 확인은 새 인식 세션에서 받는다. 읽기 중지·서비스 종료는 대기열을 비운다.

이 기능은 기본 인식기의 텍스트를 필터링하며 음성 신호의 분리나 화자 인증을 제공하지 않는다. [Android AEC](https://developer.android.com/reference/android/media/audiofx/AcousticEchoCanceler)는 앱이 제어하는 AudioRecord 세션이 필요하므로 현재 기본 인식 경로에 별도로 연결하지 않는다. 스피커와 사용자 음성이 겹칠 때의 정확도는 실제 기기에서 확인해야 한다.

PC에는 이름·직함·소장 역할과 휴가 날짜 응답을 적용했고 Vitest 573개, TypeScript·ESLint를 통과했다. 과거 대상자가 `소장님`으로 저장된 휴가·교육도 조회 중에만 현재 소장 이름으로 연결하며 저장 원본은 바꾸지 않는다. 현재 실행 폴더의 실제 서버 응답을 검증했다. Android 0.2.10은 단위 테스트 85개, APK 빌드·서명·정렬·Lint를 통과했으며 실제 태블릿의 겹쳐 말하기 검증은 남아 있다.

## 휴대폰 미디어 재생 보호 (0.2.12)

기본 음성인식 서비스의 오디오 포커스·시작음은 앱에서 차단하는 공식 옵션이 없어, 음악·영상·게임 재생 중에는 상시 듣기 세션과 호출어 인식을 쉬고 재생 종료 후 재개한다. `AudioPlaybackCallback`과 음악 스트림 상태를 읽기 전용으로 확인하며 음악 볼륨·음소거·재생 제어는 하지 않는다. 이미 미디어가 재생 중이면 첫 인식부터 열지 않고, 인식기의 짧은 효과음과 지속 재생을 구분한다. 상시 듣기 설정은 유지하고 화면·알림에 휴식 상태를 표시한다. PC 답변과 직접 입력은 유지하며 상시 듣기 OFF 상태의 명시적인 수동 마이크는 기존 동작이다. 기종별 기본 인식 서비스와 실제 음악 앱 조합은 실기기 검증 대상이다.

## 확정하지 않는 경우

- 오전/오후 없는 “2시”, “밤 12시”, 잘못된 날짜, 여러 선택지·작업이 섞인 문장.
- 등록 명령의 날짜·제목·시각 또는 종일 여부 누락.
- 반복 수정·삭제에 이번만/전체/이후 범위가 없는 경우.
- 반복 전체 시각 변경(이번만·이후 사용), 반복 주기·종일 여부 변경, 복잡한 반복 종료 조건(PC 사용).
- 근무조·조원·대체근무 편성 변경, 근무·공휴일 이벤트 직접 변경, 전체 일정 일괄 삭제.
- 현재 시각 실근무자, 잔여 연차, 수당·급여: 계산 기준 데이터가 없다.
- 휴무·비번 추정: 배정 누락을 휴무로 단정하지 않는다.
- 날씨 등 캘린더 밖의 일반 지식 질문.

모든 자연어 표현을 열거했다고 보장하지 않는다. 규칙 밖의 표현은 추측 실행하지 않고 재질문 또는 지원 예시를 제공한다. 실제 사용 중 놓친 표현은 같은 의미의 규칙과 회귀 테스트로 추가한다.

## 연결과 개발

- 발견: UDP 43827, `SHIFT_CALENDAR_DISCOVER_V1` → PC 이름·HTTP 포트 응답.
- 요청: 실행 때 할당된 TCP 포트의 `/v1/health`, `/v1/query`, `/v1/confirm`, `/v1/speech`.
- RFC1918 IPv4와 PC 루프백만 허용한다. 브라우저 Origin, 임의 경로, 초과 크기/빈도 요청은 거절한다.
- 인증·TLS 없이 동작한다. 확인 UUID는 중복 실행을 막는 작업 ID이며 사용자가 입력하는 비밀키가 아니다.
- Windows 방화벽에서 PC 앱의 사설 네트워크 통신이 허용되어야 한다. 게스트 Wi-Fi 기기 격리, 다른 공유기, UDP 차단, VPN 환경에서는 탐색이 실패할 수 있다. 방화벽은 자동 변경하지 않는다.
- 설치·빌드: [android/README.md](../android/README.md).
- 구현: `shared/voice*.ts`, `shared/shiftSummary.ts`, `main/voice`, `main/ipc/registerVoiceIpc.ts`, Android `kr.shiftcalendar.voice`.

0.2.11 응답의 `playback`은 `{ id, status, text, chunk, error? }` 형식이다. `id`는 재생 요청 UUID 또는 대기 중 요청이 없을 때 `null`, `status`는 `idle`, `queued`, `speaking`, `done`, `stopped`, `error` 중 하나다. `text`는 전체 읽기 문장, `chunk`는 현재 읽는 구간이며 `error`는 실패 시 설명이다. 화면 답변은 기존 `text` 필드를 유지한다. 구버전 Android 앱이 로컬 음성을 중복 재생하지 않도록 PC 응답의 기존 `speech`는 빈 문자열로 보낸다.

| 요청 | 용도 |
| --- | --- |
| `GET /v1/speech?id=<UUID>` | 해당 답변의 실제 PC 재생 상태 확인. ID 생략 시 현재 상태 |
| `POST /v1/speech` + `{ "action": "speak", "text": "..." }` | 다시 읽기 등 새 PC 읽기 요청을 FIFO에 추가 |
| `POST /v1/speech` + `{ "action": "stop", "id": "<UUID>" }` | 해당 재생·대기 요청 중지 |
| `POST /v1/speech` + `{ "action": "stop" }` | 전체 재생·대기 요청 중지 |

Android는 PC 재생 상태를 확인하여 현재 읽는 구간을 응답 에코 필터에 전달하고 `done`, `stopped`, `error` 이후 듣기·다음 질문 처리를 이어간다. PC 재생 오류나 연결 실패 시 Android TTS로 자동 전환하지 않는다.

인식 API: [Android SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer). Android TextToSpeech 설명과 검증 기록은 0.2.10 이하의 과거 구현에 해당한다.

## 문장 중간 호출 (0.2.2, 2026-09-09)

호출어를 인식 구간의 시작뿐 아니라 중간에서도 찾는다. 호출어의 단어 시각을 이용해 앞말을 제외하고 뒤의 질문을 보존한다. `까치야`, `까치 / 야`, `까 / 치 / 야`의 단어 분할을 처리하며 유사 단어·잘못된 시각·버퍼에 없는 과거 호출어는 거부한다. 인식 가설에서 호출 위치가 바뀌면 안정화 시간을 다시 확인한다.

단위 테스트 25개, APK 빌드·Lint(오류 0)·v2 서명·ZIP 정렬 검증을 통과했다. Windows 합성 음성 17개 중 15개가 예상대로 동작했다. 당시 문장 중간 호출 3개 중 2개는 음성 엔진이 다른 글자로 받아써 누락됐다. ‘어디까지야’ 오호출 시험은 경쟁 발음을 추가한 뒤 통과했다.

## 호출 후보 재판독 (0.2.3, 2026-09-09)

연결된 말에서 첫 음절이 다르게 인식되는 경우, `치/야`로 끝나는 유사 전사를 후보로만 사용한다. 기기에 보관한 짧은 음성 구간을 새 Vosk 인식기로 확인하며, 두 인식 결과 중 정확한 호출어가 있어야 한다. 단어 신뢰도와 같은 시간 위치의 일치도 함께 확인한다. 두 번 모두 정확한 호출어로 일치하는 경우에는 한쪽 점수만으로 거부하지 않는다.

호출 첫 음절의 시작 시각이 불확실하면 앞 여유 200 ms와 100 ms의 두 구간까지 확인한다. 명확한 경쟁 단어가 나오면 거부하고, 같은 후보의 반복 부분 결과로 계속 재판독하지 않는다. 마이크를 열어 둔 채 확인하며 녹음 버퍼를 2초로 늘려 바로 뒤의 질문을 보존한다. 후보 음성은 파일·서버에 저장하지 않고, PC에는 최종 질문 텍스트만 보낸다.

최종 합성 음성 144건에서 호출 감지는 41/72에서 55/72로 늘고 오호출은 11/72에서 7/72로 줄었다. 조정용과 별도 검증 문장은 각각 다른 24개 문장을 세 가지 속도로 합성했다. 단위 테스트 33개, APK 빌드·Lint(오류 0, 기존 경고 16개), 서명·정렬 검증을 통과했다. 650초 분량의 무음 PCM 재생 후 호출도 통과했으며 실기기 장시간 대기 시험과는 구분한다.

호출 누락 17건과 비슷한 발음의 오호출 7건은 남아 있다. 실제 태블릿은 연결되지 않아 사람 음성·마이크·절전·화면 꺼짐 조건의 안정성은 추가 확인이 필요하다. 재현 방법과 샘플별 결과는 [Android 검증 기록](../android/README.md#검증)을 참고한다.
