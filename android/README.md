# 교대근무 음성 앱

Kotlin 네이티브 앱. 현재 버전은 0.2.12(versionCode 14)이며 Android 8.0(API 26) 이상을 지원한다. PC와 같은 Wi-Fi에서 자동 연결하며 계정·비밀키 입력이 없다.

## 설치

1. 음성 연동이 포함된 PC 캘린더를 실행한다.
2. [근무물어봐-0.2.12.apk](../app/release/0.0.0/win-unpacked/근무물어봐-0.2.12.apk)를 Android 휴대폰이나 태블릿으로 옮겨 업데이트 설치한다. APK를 여는 앱의 ‘알 수 없는 앱 설치’ 허용이 필요할 수 있다.
3. 같은 Wi-Fi에서 앱을 열면 PC를 자동 발견한다. 여러 대일 때만 PC를 선택한다.
4. 첫 실행에서 마이크와 알림 권한을 허용한다. 음성 대기가 기본으로 켜진다.
5. **‘까치야, 내일 야간 누구야?’**처럼 호출어와 질문을 한 문장으로 말한다. 중간 안내 없이 바로 질문을 처리한다. 홈 화면이나 화면 꺼짐 상태의 대기 지원은 기기의 기본 음성 서비스에 따라 달라진다.
6. 등록·변경·삭제는 먼저 읽어주는 내용을 확인한 후 ‘확인’ 또는 ‘취소’를 말한다. 버튼을 누를 필요 없이 답변 이후 확인 음성을 받는다. 직접 입력과 버튼도 사용할 수 있다.

다른 말을 하던 중 나온 호출어도 찾는다. ‘오늘 뭐 먹지 까치야 내일 야간 누구야?’에서는 호출어 뒤 질문만 PC로 보낸다. ‘까치야’만 말하면 안내 없이 다음 질문을 기다린다. 인식 서비스가 호출어 뒤에서 문장을 끝내지 않도록 질문까지 이어서 말하는 것이 기본 사용법이다.

0.2.11부터 답변은 **PC의 Windows 기본 스피커**로 읽고 Android 화면에는 전체 답변을 유지한다. 현재 PC는 Supertonic 3의 한국어 F1 AI 합성 음성을 사용하며 Windows SAPI·Microsoft Heami나 Android 로컬 TTS로 읽지 않는다. ‘다시 읽기’와 ‘읽기 중지’도 PC 재생을 제어한다. 소리가 들리지 않으면 PC 기본 출력 장치와 음소거 상태를 확인한다. 이번 음성 교체와 슬래시 읽기 수정은 PC 갱신만으로 적용되며 기존 Android 0.2.11 APK를 그대로 사용할 수 있다.

화면의 `/` 등 원래 표시는 유지하고, 읽을 때 목록 구분 기호는 짧게 쉰다. 예를 들어 `일근 김민수 / 주간 A조 이영희`를 ‘슬래시’라고 읽지 않는다. PC는 최대 120자씩 5단계로 합성하고 현재 구간을 읽는 동안 다음 한 구간을 미리 만든다. 긴 목록도 순서대로 끝까지 읽는다. 합성은 PC에서만 수행하며 질문·이름·답변을 외부 TTS 서버에 보내지 않는다. 모델과 이용 조건은 [PC 음성 모델 안내](../app/THIRD_PARTY_VOICE.md)를 참고한다.

0.2.6은 호출어·질문·확인 응답·질문 버튼을 모두 Android 기본 음성인식으로 통일했다. Vosk와 한국어 모델은 APK에서 제거했다. 음성 대기 중에도 기본 서비스가 음성을 서버에서 처리할 수 있다. 앱 자체는 음성을 파일로 저장하지 않으며 PC에는 호출어 뒤 최종 질문 텍스트만 보낸다. ‘기기 내 음성인식만 사용’ 옵션과 이전 설정은 0.2.5에서 제거했다. ‘내 이름 설정’ 후 “나 내일 근무야?”를 질문할 수 있다.

## 화면이 꺼진 상태에서 사용

0.2.12는 휴대폰의 음악·영상·게임 재생을 보호한다. 미디어가 재생되는 동안 자동 듣기와 ‘까치야’ 호출 인식을 잠시 쉬고, 재생이 끝나면 다시 듣는다. 상시 듣기 설정은 켜진 채 유지하며 화면과 알림에 ‘미디어 재생 중 · 듣기 잠시 쉼’을 표시한다. 음악 볼륨·음소거·재생 버튼·오디오 포커스를 앱이 조작하지 않는다. 이미 음악이 재생 중이면 첫 인식 세션부터 시작하지 않고, 인식기의 짧은 시작·종료음은 지속 재생과 구분한다. PC 답변 재생과 직접 입력은 계속 사용할 수 있다. 상시 듣기를 끈 상태에서 사용자가 직접 누르는 수동 마이크는 기존대로 작동한다. 이 음악 보호 기능에는 Android 0.2.12 업데이트가 필요하다.

화면과 음성은 서두 없이 필요한 항목부터 답한다. 하루 근무자는 `일근 이름 / 주간 A조 이름 / 야간 B조 이름`을 세 줄로 표시한다. 특정 근무만 물으면 해당 줄만, 인원은 숫자만, 일정의 시간·장소는 요청한 항목만 답한다. 근무에서 제외되는 휴가·교육자는 이름과 부재 설명을 모두 생략하며 전원 부재면 ‘없음’으로 답한다. 반차·시간차 대상자는 일부 시간 근무하므로 이름과 인원에 포함하되 휴가 뱃지와 사유는 말하지 않는다. 휴가·교육 자체를 묻는 질문에서는 대상자를 표시한다. PC 오늘의 근무 카드도 전원 부재인 조는 `A조 근무자 없음`, 구성원 미등록은 `A조 미지정`으로 구분한다. 등록·변경·삭제 확인에는 대상·날짜·반복 범위를 유지하며 완료 안내는 한 줄로 끝낸다. 답변 생성은 PC에서 하므로 **PC 앱도 함께 업데이트**해야 한다.

0.2.11 화면은 가로 방향으로 고정하지 않는다. 기기의 `smallestScreenWidthDp`가 600 이상이고 현재 창 폭도 600dp 이상일 때만 태블릿용 두 영역을 사용한다. 스마트폰은 가로로 돌려도 휴대폰용 세로 배치를 유지하며 태블릿도 좁은 분할 창에서는 휴대폰 배치를 사용한다. 회전이나 분할 화면으로 창 크기가 바뀌면 다시 배치하며, 큰 글자 설정에서는 버튼을 세로로 쌓는다. 이름·배터리 설정은 상단 ‘설정’에 있다. 키보드로 높이가 부족해지면 질문 입력과 보내기를 우선 표시한다.

빠른 설정에는 새 모양 아이콘의 **‘까치야 상시 듣기’** 타일을 제공한다. Android 13(API 33) 이상은 앱 설정의 ‘빠른 설정에 상시 듣기 추가’로 추가하고, 이전 버전은 빠른 설정 편집 화면에서 직접 추가한다. 타일을 켜면 마이크 서비스 시작 제약에 따라 앱 화면을 열어 권한을 확인하고 대기를 시작한다. 타일을 끄면 대기를 즉시 종료하며 타일 표시는 실제 서비스 상태와 동기화한다.

상시 대기에는 마이크 포그라운드 서비스와 CPU 대기 잠금을 사용한다. 대기 알림의 ‘대기 끄기’나 앱 버튼으로 종료할 수 있다. 0.2.10부터 음성 답변 중에도 ‘까치야 + 질문’을 듣고 대기열에 저장한다. 호출어 없는 대화와 읽는 답변의 일치·유사 전사는 제외한다. 마지막 재생 구간이 끝나면 먼저 들어온 질문부터 처리한다. 일반 질문을 듣지 못하면 약 18초 후 호출어 대기로 돌아간다.

앱의 ‘배터리 제한 설정 열기’에서 배터리를 ‘제한 없음’으로 설정하면 장시간 대기에 도움이 된다. 제조사 절전 설정, 통화·다른 녹음 앱, 마이크 권한 철회에 따라 중단될 수 있다. **휴대폰 재부팅·강제 종료 후에는 앱을 다시 열어야 한다.** Android의 마이크 백그라운드 시작 제한 때문에 부팅 수신기로 몰래 재시작하지 않는다. 화면 꺼짐과 프로세스 종료는 서로 다른 상태다. [Android 마이크 서비스 제약](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone).

실제 목소리·소음·마이크에 따라 인식률과 응답 지연이 달라진다. 기본 서비스가 호출어를 다른 글자로 받아쓰면 호출되지 않을 수 있고, 비슷한 말을 ‘까치야’로 받아쓰면 오호출할 수 있다. 일정 변경은 내용을 읽은 뒤 음성 확인을 받아 실행한다.

APK에는 음성 모델 다운로드·압축 해제 과정이 없다. 질문 해석과 답변 문장 생성은 PC의 키워드 규칙으로 처리하며 LLM API를 사용하지 않는다. PC에서 완성된 문장을 소리로 바꾸는 단계에만 로컬 AI 음성 모델을 사용한다. 이 모델 약 398 MB는 PC 빌드 준비 시 고정 revision과 SHA-256으로 검증해 포함한다. Android 기본 음성인식 서비스의 서버 처리 가능성은 별개다.

0.2.6부터 `LiveQuestionRecognizer`의 한 세션에서 호출어와 질문 전체를 듣는다. 부분 인식은 화면에만 표시하고 최종 문장에서 호출어를 분리해 한 번 제출한다. 0.2.7은 정상 결과와 무음 종료 후 기본 인식기 연결을 재사용한다. 정상 대기마다 인식기를 없애고 새로 만들거나 ‘연결 중’을 반복 표시하지 않으며 같은 화면 상태를 다시 전달하지 않는다. 사용자 취소·실제 서비스 오류·응답 정지에는 연결을 새로 만든다. 일시 오류는 1~30초까지 간격을 늘려 재시도하며 요청 제한은 30초 대기한다. 권한·한국어 서비스가 없으면 대기를 끄고 화면에 이유를 표시한다. Android `SpeechRecognizer`는 연속 상시 인식을 위한 API가 아니므로 서비스 자체의 세션 사이 공백·요청 제한·배터리 및 네트워크 사용량은 기기에 따라 달라진다. [Android 기본 음성인식](https://developer.android.com/reference/android/speech/SpeechRecognizer).

이전 0.2.1~0.2.3은 버퍼 인식 미지원·시간 초과에서 Vosk의 질문 전사를 자동 사용해 문장 인식이 나빠질 수 있었다. 0.2.4는 자동 대체를 없앴지만 버퍼 입력과 기기 내 전용 옵션이 남아 있었다. 0.2.5에서는 이 분기도 없앴다.

대기 안내는 기본 인식 서비스의 준비 콜백 이후 표시한다. 정상 재시작은 기존 대기 상태를 유지하며 준비가 1.5초 넘게 지연되면 화면에 알린다. 준비 콜백이 10초 동안 없거나 전체 세션이 45초간 끝나지 않으면 재연결한다. 준비되지 않은 세션에서 바로 반환된 무음 오류도 실제 오류로 처리해 빠른 반복 재시작을 막는다. PC 음성 답변의 종료·중단·오류를 확인해 다시 대기한다. 대기를 끄면 마이크·인식 서비스를 해제하고 PC 읽기 중지를 요청한다.

지원 표현은 [음성 명령 안내](../docs/voice-assistant-design.md)를 참고한다. PC를 찾지 못하면 PC 실행, 같은 공유기, PC 설정의 휴대폰 연결, Windows 방화벽 사설 네트워크 허용과 공유기의 기기 격리를 확인한다.

‘일정 알려줘’에는 반복업무·중요·출장·교육·일반 다섯 타입만 표시한다. `반복업무: 장비점검`, `교육: 안전교육`처럼 타입별 제목을 전부 나열하며 날짜·시간·대상자 설명은 생략한다. 일정 건수와 다음 일정의 대상도 이 다섯 타입이다. 날짜·시간·장소를 직접 물으면 요청한 정보를 제공하고, 근무·휴가·공휴일·운용중지작업 등 타입을 직접 물으면 해당 타입을 조회한다.

‘휴가 누구야’는 `김민수-연차`처럼 이름과 등록된 뱃지명만 답한다. 날짜·제목은 읽지 않고 같은 이름·뱃지를 합친다. 한 사람의 여러 종류는 `김민수-연차·시간차(13:00~14:00)`처럼 표시한다. ‘휴가 언제야’는 오늘부터 저장된 예정 휴가를 날짜순으로 전부 답하며, 다음 한 건이나 90일로 제한하지 않는다. 특정 날짜·달을 말하면 그 기간만 조회한다. 시간차는 저장된 시각 메모·종류·제목의 시각을 읽어 `9월 16일 김민수 시간차(오후 1시~오후 3시)`처럼 한 번만 표시한다. 날짜만 자정으로 저장돼 있어도 ‘종일(시각 미등록)’을 붙이지 않는다. 실제 시각이 없으면 날짜·이름·뱃지만 답하며, 시각을 직접 물을 때만 미등록을 안내한다. 이 응답 수정은 PC 갱신으로 기존 Android 0.2.10에도 적용된다.

사람별 조회는 `민수`, `민수씨`, `민수님`처럼 성을 생략해도 등록된 이름이 하나로 정해지면 처리한다. `김민수 대리`, `민수 과장님`처럼 이름 뒤에 직함을 붙여도 된다. 이름이 겹치면 성을 포함해 다시 질문하도록 안내한다. `소장`, `소장님`은 근무 설정에서 소장으로 표시되는 첫 번째 일근자를 뜻한다. `민수씨 언제 연차야?`에는 `9월 16일 김민수 연차`처럼 답하며, 시간차를 제외한 휴가에는 시각·종일·시각 미등록 문구를 붙이지 않는다. 이 변경은 PC 갱신으로 적용된다.

`김수원 과장 휴가 언제야?`처럼 이름이 잘못 받아써진 조회도 등록된 `김수헌`에 제한적으로 연결한다. 정확한 등록 이름이 있으면 우선하고, 유사 이름은 같은 성의 한글 세 글자 중 이름 한 음절만 다르며 그 음절의 초·중·종성 차이가 두 자리 이하일 때만 허용한다. 후보가 여러 명이면 되물으며 `김수헌`처럼 이름만 답해 선택할 수 있다. 이 보정은 조회 전용으로, 일정 등록·변경·삭제에는 적용하지 않는다.

`A조 근무자 누구야?`처럼 조만 지정하면 휴가 여부와 관계없이 설정된 조 명단을 그대로 답한다. `오늘 A조 근무자 누구야?`, `A조 야간 누구야?`처럼 날짜나 주간·야간을 지정하면 해당 날짜의 실제 근무와 부재를 반영한다.

연도를 생략한 월·날짜는 PC의 오늘에서 가장 가까운 연도를 사용한다. 12월의 ‘1월 달력 알려줘’는 다음 해 1월, 1월의 ‘12월 달력 알려줘’는 지난 해 12월로 이동한다. 같은 거리이면 미래를 선택하며, 연도를 명시하거나 올해·내년·작년을 말하면 지정한 연도를 따른다. 날짜 범위는 연말·연초를 포함해 시작과 끝을 함께 해석한다.

과거 0.2.8에서는 긴 목록의 제한을 없애고 Android TTS 입력 길이에 맞춰 전체 답변을 나누어 읽었다. 현재 PC는 줄과 최대 120자 길이에 맞게 구간을 나누어 순서대로 읽으며 전체 답변의 시간 제한을 두지 않는다. PC 재생의 준비나 개별 구간이 멈추면 오류를 알리고, ‘읽기 중지’는 남은 합성과 재생도 취소한다. Android 0.2.11의 재생 상태 확인 방식은 그대로 사용한다.

사람을 지정한 근무 질문은 `주간 A조입니다.`, `근무 없음`처럼 근무 여부만 답한다. 휴가자는 화면에 `김민수-연차`, 음성은 ‘김민수, 연차.’로 한 번만 읽고 `13:00`은 ‘오후 1시’로 읽는다. 제목에 이름·연차가 이미 있거나 여러 날을 조회해도 날짜 서두와 같은 이름·뱃지를 반복하지 않는다. 날짜·일정 선택을 되물을 때는 질문만 짧게 말하며 상시 대기 모드에서는 ‘내일’, ‘오후’, ‘두 번째’ 같은 답을 바로 듣는다. 조회 선택 맥락은 2분간 유지한다. 등록·변경·삭제는 대상과 범위를 읽은 뒤 별도로 확인받는다.

과거 0.2.9는 마지막 음성의 재생 완료 콜백 뒤에 두던 350ms 대기를 없앴다. 답변을 읽는 동안 인식기 객체를 미리 준비하고 Android 13 이상에서는 같은 인식 요청의 지원 여부도 미리 확인했다. 당시에는 TTS 중 마이크 입력을 시작하지 않았으며 0.2.10부터 답변 중 다음 질문을 받는다. 이미 연결된 정상 인식기는 계속 재사용한다. 실제 마이크 준비 시점은 기기의 인식 서비스에 달려 있다. 기본 인식 API에는 앱이 마이크 게인을 최대로 지정하는 설정이 없으므로 최대 감도를 설정했다고 표시하지 않는다. [SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer), [AGC의 오디오 세션 조건](https://developer.android.com/reference/kotlin/android/media/audiofx/AutomaticGainControl).

0.2.10은 답변 중 마이크 캡처를 허용한다. 확정된 인식만 대기열에 넣고 같은 질문의 중복 결과를 합친다. 한 문장에 ‘까치야’를 여러 번 불러도 각 질문을 나누며, 대기 개수를 화면에 표시한다. 끝나기 직전에 호출어가 부분 인식되었다면 최대 10초간 최종 결과를 기다린다. 부분 결과만으로 명령을 실행하지 않는다. 처리할 등록·변경·삭제 미리보기가 있으면 먼저 새 확인 음성을 받고 대기 질문을 이어서 처리한다. 답변 중 들린 ‘확인·취소’는 미래 작업의 승인으로 저장하지 않는다. ‘읽기 중지’와 음성 대기 종료는 질문 대기열도 비운다.

응답 제외는 인식 텍스트 비교 방식이며 화자 식별이나 음향 에코 제거를 보장하지 않는다. 기기의 기본 인식 서비스가 스피커 소리와 사용자 목소리를 섞어 받아쓰면 질문이 누락되거나 잘못 인식될 수 있다. 직접 제어하는 오디오 세션을 요구하는 [Android AEC](https://developer.android.com/reference/android/media/audiofx/AcousticEchoCanceler)는 기본 `SpeechRecognizer` 연결에 별도로 적용하지 않는다. 실제 태블릿의 겹쳐 말하기 정확도는 실기기 검증 대상이다.

0.2.11은 답변의 `playback`에 `id`, `status`, 전체 `text`, 현재 읽는 `chunk`, 선택적 `error`를 받는다. `GET /v1/speech`로 상태를 확인하고 `POST /v1/speech`로 다시 읽기·중지를 요청한다. PC는 구버전 앱이 소리를 중복 재생하지 않도록 답변의 기존 `speech` 필드를 빈 문자열로 보낸다. 상세 규약은 [연결과 개발](../docs/voice-assistant-design.md#연결과-개발)을 참고한다.

## 빌드

JDK 17 이상(검증 JDK 21), Android SDK Platform 36와 Build Tools 35.0.0이 필요하다. Gradle Wrapper 8.13을 포함한다. 음성 모델과 별도 인식 라이브러리는 빌드에 포함하지 않는다. Android Studio에서 이 폴더를 열거나 다음 명령을 실행한다.

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-21'
$env:ANDROID_HOME = 'C:\path\to\android-sdk'
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

한글 Windows 사용자 경로에서 Gradle 작업 프로세스가 시작되지 않으면 ASCII 경로의 캐시와 임시 폴더를 사용한다. SDK는 `ANDROID_HOME` 또는 로컬 전용 `local.properties`의 `sdk.dir`로 설정한다.

```powershell
$env:GRADLE_USER_HOME = 'C:\android-build\gradle'
$env:TEMP = 'C:\android-build\tmp'
$env:TMP = $env:TEMP
$env:JAVA_OPTS = '-Djava.io.tmpdir=C:/android-build/tmp'
New-Item -ItemType Directory -Force $env:GRADLE_USER_HOME, $env:TEMP | Out-Null
.\gradlew.bat --no-daemon '-Dorg.gradle.jvmargs=-Xmx1536m -Dfile.encoding=UTF-8 -Djava.io.tmpdir=C:/android-build/tmp' assembleDebug testDebugUnitTest lintDebug
```

APK는 설치 가능한 **디버그 서명 테스트 버전**이다. 다른 컴퓨터에서 빌드하면 디버그 서명이 달라 업데이트 설치가 실패할 수 있다. 지속 배포에는 관리하는 릴리스 서명 키로 서명해야 한다. Play Store 등록·배포는 포함하지 않는다. 서명 파일·SDK·캐시·빌드 결과는 Git에 포함하지 않는다.

PC는 `app`에서 `npm run build`로 현재 실행 폴더인 `app/release/0.0.0/win-unpacked`에 갱신한다. APK 빌드 원본은 `android/app/build/outputs/apk/debug/app-debug.apk`이며, PC 빌드가 끝난 뒤 최신 APK 한 개만 같은 실행 폴더에 버전명으로 복사한다. 다른 배포 폴더와 이전 버전 복사본은 만들지 않는다.
