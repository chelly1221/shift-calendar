# 교대근무 음성 앱

Kotlin 네이티브 앱. Android 8.0(API 26) 이상. PC와 같은 Wi-Fi에서 자동 연결하며 계정·비밀키 입력이 없다.

## 설치

1. 음성 연동이 포함된 PC 캘린더를 실행한다.
2. [근무물어봐-0.2.8.apk](../app/release/0.0.0/근무물어봐-0.2.8.apk)를 Android 태블릿으로 옮겨 업데이트 설치한다. APK를 여는 앱의 ‘알 수 없는 앱 설치’ 허용이 필요할 수 있다.
3. 같은 Wi-Fi에서 앱을 열면 PC를 자동 발견한다. 여러 대일 때만 PC를 선택한다.
4. 첫 실행에서 마이크와 알림 권한을 허용한다. 음성 대기가 기본으로 켜진다.
5. **‘까치야, 내일 야간 누구야?’**처럼 호출어와 질문을 한 문장으로 말한다. 중간 안내 없이 바로 질문을 처리한다. 홈 화면이나 화면 꺼짐 상태의 대기 지원은 기기의 기본 음성 서비스에 따라 달라진다.
6. 등록·변경·삭제는 먼저 읽어주는 내용을 확인한 후 ‘확인’ 또는 ‘취소’를 말한다. 버튼을 누를 필요 없이 답변 이후 확인 음성을 받는다. 직접 입력과 버튼도 사용할 수 있다.

다른 말을 하던 중 나온 호출어도 찾는다. ‘오늘 뭐 먹지 까치야 내일 야간 누구야?’에서는 호출어 뒤 질문만 PC로 보낸다. ‘까치야’만 말하면 안내 없이 다음 질문을 기다린다. 인식 서비스가 호출어 뒤에서 문장을 끝내지 않도록 질문까지 이어서 말하는 것이 기본 사용법이다.

답변은 한국어 TTS로 읽는다. 한국어 음성 서비스가 없으면 화면 답변을 사용한다. 0.2.6은 호출어·질문·확인 응답·질문 버튼을 모두 Android 기본 음성인식으로 통일했다. Vosk와 한국어 모델은 APK에서 제거했다. 음성 대기 중에도 기본 서비스가 음성을 서버에서 처리할 수 있다. 앱 자체는 음성을 파일로 저장하지 않으며 PC에는 호출어 뒤 최종 질문 텍스트만 보낸다. ‘기기 내 음성인식만 사용’ 옵션과 이전 설정은 0.2.5에서 제거했다. ‘내 이름 설정’ 후 “나 내일 근무야?”를 질문할 수 있다.

## 화면이 꺼진 상태에서 사용

0.2.4부터 화면과 음성은 서두 없이 필요한 항목부터 답한다. 하루 근무자는 `일근 이름 / 주간 A조 이름 / 야간 B조 이름`을 세 줄로 표시한다. 특정 근무만 물으면 해당 줄만, 인원은 숫자만, 일정의 시간·장소는 요청한 항목만 답한다. 근무에서 제외되는 휴가·교육자는 이름과 부재 설명을 모두 생략하며 전원 부재면 ‘없음’으로 답한다. 반차·시간차는 이름 옆에 종류를 표시하고 인원에 포함한다. 휴가·교육 자체를 묻는 질문에서는 대상자를 표시한다. 날짜 범위·다음 일정에는 날짜를 유지하며 배정·구성원 미등록을 실제 근무자 없음과 구분한다. 등록·변경·삭제 확인에는 대상·날짜·반복 범위를 유지하며 완료 안내는 한 줄로 끝낸다. 답변 생성은 PC에서 하므로 **PC 앱도 함께 업데이트**해야 한다.

화면은 태블릿 가로 방향을 기본으로 한다. 왼쪽에는 실제 음성 대기 상태와 PC 연결, 오른쪽에는 넓은 답변과 질문 입력을 배치한다. 이름·배터리 설정은 상단 ‘설정’에 있다. 좁은 분할 창에서는 세로로 배치하며, 키보드로 높이가 부족해지면 질문 입력과 보내기를 우선 표시한다.

상시 대기에는 마이크 포그라운드 서비스와 CPU 대기 잠금을 사용한다. 대기 알림의 ‘대기 끄기’나 앱 버튼으로 종료할 수 있다. 음성 답변 중에는 인식을 멈추므로 자신의 답변을 새 명령으로 실행하지 않는다. 질문을 듣지 못하면 약 18초 후 호출어 대기로 돌아간다.

앱의 ‘배터리 제한 설정 열기’에서 배터리를 ‘제한 없음’으로 설정하면 장시간 대기에 도움이 된다. 제조사 절전 설정, 통화·다른 녹음 앱, 마이크 권한 철회에 따라 중단될 수 있다. **휴대폰 재부팅·강제 종료 후에는 앱을 다시 열어야 한다.** Android의 마이크 백그라운드 시작 제한 때문에 부팅 수신기로 몰래 재시작하지 않는다. 화면 꺼짐과 프로세스 종료는 서로 다른 상태다. [Android 마이크 서비스 제약](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone).

실제 목소리·소음·마이크에 따라 인식률과 응답 지연이 달라진다. 기본 서비스가 호출어를 다른 글자로 받아쓰면 호출되지 않을 수 있고, 비슷한 말을 ‘까치야’로 받아쓰면 오호출할 수 있다. 일정 변경은 내용을 읽은 뒤 음성 확인을 받아 실행한다.

APK에는 음성 모델 다운로드·압축 해제 과정이 없다. 생성형 AI·LLM API는 사용하지 않으며 질문 해석과 답변은 PC의 키워드 규칙으로 처리한다.

0.2.6부터 `LiveQuestionRecognizer`의 한 세션에서 호출어와 질문 전체를 듣는다. 부분 인식은 화면에만 표시하고 최종 문장에서 호출어를 분리해 한 번 제출한다. 0.2.7은 정상 결과와 무음 종료 후 기본 인식기 연결을 재사용한다. 정상 대기마다 인식기를 없애고 새로 만들거나 ‘연결 중’을 반복 표시하지 않으며 같은 화면 상태를 다시 전달하지 않는다. 사용자 취소·실제 서비스 오류·응답 정지에는 연결을 새로 만든다. 일시 오류는 1~30초까지 간격을 늘려 재시도하며 요청 제한은 30초 대기한다. 권한·한국어 서비스가 없으면 대기를 끄고 화면에 이유를 표시한다. Android `SpeechRecognizer`는 연속 상시 인식을 위한 API가 아니므로 서비스 자체의 세션 사이 공백·요청 제한·배터리 및 네트워크 사용량은 기기에 따라 달라진다. [Android 기본 음성인식](https://developer.android.com/reference/android/speech/SpeechRecognizer).

이전 0.2.1~0.2.3은 버퍼 인식 미지원·시간 초과에서 Vosk의 질문 전사를 자동 사용해 문장 인식이 나빠질 수 있었다. 0.2.4는 자동 대체를 없앴지만 버퍼 입력과 기기 내 전용 옵션이 남아 있었다. 0.2.5에서는 이 분기도 없앴다.

대기 안내는 기본 인식 서비스의 준비 콜백 이후 표시한다. 정상 재시작은 기존 대기 상태를 유지하며 준비가 1.5초 넘게 지연되면 화면에 알린다. 준비 콜백이 10초 동안 없거나 전체 세션이 45초간 끝나지 않으면 재연결한다. 준비되지 않은 세션에서 바로 반환된 무음 오류도 실제 오류로 처리해 빠른 반복 재시작을 막는다. 음성 답변의 종료·중단·오류를 모두 처리하고, 종료 알림이 누락되어도 재생 상태를 확인해 다시 대기한다. 대기를 끌 때는 화면 연결 여부와 관계없이 마이크·음성 서비스·TTS를 즉시 해제한다.

지원 표현은 [음성 명령 안내](../docs/voice-assistant-design.md)를 참고한다. PC를 찾지 못하면 PC 실행, 같은 공유기, PC 설정의 휴대폰 연결, Windows 방화벽 사설 네트워크 허용과 공유기의 기기 격리를 확인한다.

‘일정 알려줘’에는 일반·운용중지작업·반복업무·출장·교육·중요 등 활동 일정을 표시하고 근무·휴가·공휴일을 제외한다. 일정 건수와 다음 일정에도 같은 기준을 적용한다. 근무·휴가·공휴일을 직접 물으면 각각 조회한다.

‘휴가 누구야’는 `김민수-연차`처럼 이름과 등록된 뱃지명만 답한다. 날짜·제목은 읽지 않고 같은 이름·뱃지를 합친다. 한 사람의 여러 종류는 `김민수-연차·시간차(13:00~14:00)`처럼 표시한다. ‘휴가 언제야’처럼 날짜를 직접 물으면 날짜를 제공한다.

연도를 생략한 월·날짜는 PC의 오늘에서 가장 가까운 연도를 사용한다. 12월의 ‘1월 달력 알려줘’는 다음 해 1월, 1월의 ‘12월 달력 알려줘’는 지난 해 12월로 이동한다. 같은 거리이면 미래를 선택하며, 연도를 명시하거나 올해·내년·작년을 말하면 지정한 연도를 따른다. 날짜 범위는 연말·연초를 포함해 시작과 끝을 함께 해석한다.

0.2.8은 긴 목록도 전부 표시하고 끝까지 읽는다. 일정·휴가자 20개, 근무표 31일, 음성 3줄로 줄이던 제한을 없앴다. 기기의 TTS 입력 제한에 맞춰 여러 구간을 순서대로 읽고 전체 답변이 끝난 뒤 마이크 대기를 재개한다. ‘읽기 중지’나 새 질문은 남은 구간도 취소한다. 음성 엔진 오류나 구간 재생 정지는 화면에 알리고 대기로 복귀한다.

사람을 지정한 근무 질문은 `주간 A조입니다.`, `연차입니다.`처럼 상태만 답한다. 전체 근무자에서는 전일 부재자를 계속 제외한다. 일반 일정 목록은 `오후 2시 안전교육`처럼 시간·제목 순서이며 종일 일정은 제목만 표시한다. 휴가자는 화면에 `김민수-연차`, 음성은 ‘김민수, 연차.’로 읽고 `13:00`은 ‘오후 1시’로 읽는다. 날짜·일정 선택을 되물을 때는 질문만 짧게 말하며 상시 대기 모드에서는 ‘내일’, ‘오후’, ‘두 번째’ 같은 답을 바로 듣는다. 조회 선택 맥락은 2분간 유지한다. 등록·변경·삭제는 대상과 범위를 읽은 뒤 별도로 확인받는다.

## 빌드

JDK 17 이상(검증 JDK 21), Android SDK Platform 36와 Build Tools 35.0.0이 필요하다. Gradle Wrapper 8.13을 포함한다. 음성 모델과 별도 인식 라이브러리는 빌드에 포함하지 않는다. Android Studio에서 이 폴더를 열거나 다음 명령을 실행한다.

```powershell
$env:JAVA_HOME = 'C:\path\to\jdk-21'
$env:ANDROID_HOME = 'C:\path\to\android-sdk'
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug
```

한글 Windows 사용자 경로에서 Gradle 작업 프로세스가 시작되지 않으면 ASCII 경로의 캐시와 임시 폴더를 사용한다. SDK는 `ANDROID_HOME` 또는 로컬 전용 `local.properties`의 `sdk.dir`로 설정한다.

```powershell
$env:GRADLE_USER_HOME = 'C:\android-build\gradle'
$env:TEMP = 'C:\android-build\tmp'
$env:TMP = $env:TEMP
$env:JAVA_OPTS = '-Djava.io.tmpdir=C:/android-build/tmp'
New-Item -ItemType Directory -Force $env:GRADLE_USER_HOME, $env:TEMP | Out-Null
.\gradlew.bat --no-daemon '-Dorg.gradle.jvmargs=-Xmx1536m -Dfile.encoding=UTF-8 -Djava.io.tmpdir=C:/android-build/tmp' assembleDebug testDebugUnitTest lintDebug
```

APK는 설치 가능한 **디버그 서명 테스트 버전**이다. 다른 컴퓨터에서 빌드하면 디버그 서명이 달라 업데이트 설치가 실패할 수 있다. 지속 배포에는 관리하는 릴리스 서명 키로 서명해야 한다. Play Store 등록·배포는 포함하지 않는다. 서명 파일·SDK·캐시·빌드 결과는 Git에 포함하지 않는다.

## 검증

0.2.8: APK 빌드·v2 서명·16 KB ZIP 정렬 통과. Android Lint 오류 0, 경고 15. PC Vitest 500개, TypeScript·ESLint 통과. 긴 일정·휴가자·근무표 전체 반환, 사람별 상태, 시간·제목 순서, 이름·뱃지 음성 표기, 날짜·일정 선택 후속 응답과 만료를 검사했다. Android 단위 테스트 66개로 전체 텍스트 보존, 90초를 넘는 연속 읽기, 중지·새 답변·누락·중복 콜백·음성 엔진 오류·읽기 시작 지연 처리를 검사했다. 실제 태블릿에서의 장시간 읽기·마이크 인식은 별도 검증이 필요하다.

0.2.7: Android 단위 테스트 57개, APK 빌드·v2 서명·16 KB ZIP 정렬 통과. Android Lint 오류 0, 경고 15. 가짜 인식 서비스로 정상 인식·무음 1,000회를 한 연결에서 처리하고, 취소·오류 이후 늦은 결과 차단과 준비 지연 복구를 검사했다. 실제 태블릿이 연결되어 있지 않아 장시간 대기와 실제 목소리 인식은 실기기 검증이 남아 있다. PC는 Vitest 473개, TypeScript·ESLint를 통과했다.

0.2.6: 단위 테스트 49개, APK 빌드·v2 서명·16 KB ZIP 정렬 검사 통과. Android Lint 오류 0, 경고 15. 이전 APK와 서명 인증서가 같고 APK에 Vosk 모델·네이티브 라이브러리가 없음을 확인했다. 검사는 한 문장의 호출어·질문 분리, 띄어쓰기·문장부호·앞말 처리, 일반 대화 무시, 중복 결과 차단, 확인 대기 중 새 변경 차단, 100회 답변 후 대기 복귀, 무음·오류·요청 제한의 재시도를 포함한다. 실제 기기가 연결되지 않아 사람 목소리·기본 서비스·화면 꺼짐·장시간 대기 검증은 남아 있다. 아래 Vosk 합성음성 수치는 과거 버전 기록이며 0.2.6 기본 인식기의 정확도를 나타내지 않는다.
